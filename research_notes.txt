AUTHOR CODE REVIEW - OBSERVED BEHAVIOR, NOT INCIDENT CONFIRMATION
Source: https://raw.githubusercontent.com/koumajos/CESNET-TimeSeries24-CD/main/create_datapoints.py
The published collector initializes its time anchor from the first received
flow's end time and advances its anchor by the configured aggregation period,
which defaults to 600 seconds. This permits a restart to establish a new
phase, but does not prove a restart caused the observed phase shifts.
No explanation for these exact five boundaries was located in the reviewed
paper, collector code, or public example-repository issue listing.

CONSERVATIVE HANDLING PROPOSAL - NOT YET IMPLEMENTED
Keep timestamps and measurements unchanged; mark each non-600-second
transition as a boundary. Build future input/target windows only within a
continuous block, checking the complete origin-to-target path for longer
horizons as well as the input history. Do not silently bridge boundaries,
fill zeros, interpolate, relabel timestamps, or stretch byte-count duration.
Boundary-adjacent measurement durations remain uncertain and require a
separate rule before any rate conversion. This proposal is not a correction
of the underlying timestamps and does not address the documented probe outage.

OBSERVED PUBLIC CODE: DataPointIP.update adds forward and reverse bytes.

its aggregation anchor and adds the current flow before checking whether
the interval should close. These are code observations, not a verification
of the exact deployment that produced every released observation.

WORKING PROJECT DEFINITION
Target source: n_bytes for a single institution series.
Future derived column: recorded_traffic_mbps.
Formula: n_bytes * 8 / (600 * 1,000,000).
Units: nominal recorded megabits per second; 1 megabit = 1,000,000 bits.
Use the documented nominal interval, not a timestamp discontinuity's length.
This is a constant normalization of recorded volume, not recovered traffic.

CESNET INTERVAL UNITS
The interval is 600 seconds, not the original GEANT plan's 900 seconds.
Deficit volume in decimal MB = sum(max(actual-capacity,0)) * 600 / 8.
Flat traffic: 100 Mbps demand with 10% margin gives 110 Mbps capacity and no
shortfall. A jump to 200 Mbps with capacity still 110 Mbps gives a 90 Mbps
deficit, equivalent to 6,750 MB over one nominal 10-minute interval.
This is simulated unserved demand, not observed packet loss.
Mean overprovision is mean(max(capacity-actual,0)); aggregate utilization is
sum(min(actual,capacity))/sum(capacity), undefined for zero total capacity.
The simulation covers only eligible intervals, without integrating exclusions.
